# 进程

> 任务的调度体，任务资源的管理者

## 进程概述

操作系统实现多任务分为：分时操作系统，实时操作系统，批处理操作系统

多任务需要考虑的问题较多，为了解决每个问题，需要设计对应的数据结构和算法：
- 把解决问题的数据当作**正文**
- 把数据的头结点作为管理任务的**进程头**，即PCB块（Process Control Block），PCB块内有指向数据地址的指针（如代码段，数据段，堆区，栈区）

每个任务都有自己的数据，将必备的数据封装成一个结构体`task_struct`，包含各种进程头，pid，context，状态，优先级数据等，还有内存映射表`memory map`，进程的切换就是`task_struct`和`memory map`的切换

- 程序：静态的文件，包含代码段和数据段，程序存储位置在磁盘，运行位置在虚拟内存，通过系统的初始化代码转移到内存上
- 进程：进程头+正文组成的运行时的资源，不同进程的资源是独立的，进程的虚拟地址由MMU根据虚拟地址和pid计算映射到物理地址

Linux的进程采用树状结构管理

## 进程实现

- `fork`创建进程
- `execl`替换进程
- `exit`退出进程
- `wait`回收子进程资源

进程的资源是独立的

## 进程状态切换

Linux`/proc/`目录下进程号对应的目录内就是PCB的信息，包括`fd`目录内有文件描述符，进程退出后PCB信息仍然存在，但大部分指针失效，此时为僵尸进程，直到父进程回收子进程资源

进程是由PCB管理的，进程最终要运行需要CPU通过PCB找到PC指针

OS管理策略：
- 进程得到CPU资源，运行
- 进程放弃CPU资源
	- 主动放弃：CPU时间片用完了（分时OS）
	- 被动放弃：资源不全，如`fgets`，放弃CPU等待唤醒操作，获取到了资源再返回执行

进程3状态：
- 运行态：Linux下为R态（running）
- 阻塞态：Linux下有D态，S态
- 就绪态：Linux下为R态（runnable）

# 线程

> 任务的调度体，共享当前进程的资源

## 线程概述

进程：具备调度能力（task_struct），具备内存映射表的独立性（memory map）
进程切换：CPU重新加载新进程的task_struct和memory map，时间开销较大

![[Pasted image 20260821174705.png | 进程]]

线程：任务只具备调度能力，内存是共享的，避免了内存切换的时间开销，即轻量级进程；每个线程都有独立的task_struct，内部指针指向同一片memory map，线程依赖于某个进程；由于有task_struct，具有进程状态切换

![[Pasted image 20260821175109.png | 线程]]

进程和线程的区别：
1. 具备调度能力
2. 进程和进程之间有独立的内存映射表，进程和进程的内存访问是独立的，互不影响
3. 线程和线程之间共享当前所在进程的内存映射表，线程和线程的内存访问可以共享

## 线程实现

依赖第三方库`<pthread.h>`，编译加上选项`-pthread`

- `pthread_create`创建线程
- `pthread_self`获取线程号
- `pthread_exit`退出线程
- `pthread_join`，`pthread_detach`回收线程资源

# 任务间通信

- 临界资源：同一时刻只能由一个任务使用的资源
- 临界区：程序访问临界资源的代码段
- 同步：多个任务对临界资源的访问有明确的先后顺序
- 互斥：一旦资源被某个任务占用，其他任务就不能访问该资源

线程间通信：

同一个进程下的线程共享memory map，通过共享的内存进行通信，但需要处理临界资源的同步互斥问题
临界资源：代码段，数据段（全局区，static区），堆段，内核提供的资源

进程间通信：

不同进程不共享用户空间资源，但共享内核空间，可以通过内核区进行通信
临界资源：内核提供的资源

## 同步互斥

- 同步：协作关系
- 互斥：竞争关系

多任务访问临界资源，划分临界区的设计准则：
1. 空闲让进
2. 忙则等待
3. 有限等待
4. 让权等待

### 互斥

#### 软件机制

几种错误：单标记法，双标记法，peterson算法

##### 单标记法

定义一个整型变量`int turn;`（本质上是临界资源）表示程序进入临界区的权限，值为0表示进程0可以进入临界区，值为1表示进程1可以进入临界区

```Cpp title:"进程0"
while(true){
	while(turn!=0);    //等待turn的值为0
	/*临界区*/
	turn=1;    //将权限转让给进程1
	/*剩余区*/
}
```

```Cpp title:"进程1"
while(true){
	while(turn!=1);    //等待turn的值为1
	/*临界区*/
	turn=0;    //将权限转让给进程0
	/*剩余区*/
}
```

违背了**空闲让进**准则

##### 双标记法

定义两个整形变量`int flags[2];`（本质上是临界资源），`flags[i]`的值为1表示进程i有进入临界区的权限，值为0表示进程i没有进入临界区的权限

```Cpp title:"进程i"
while(true){
	while(flags[j]);    //等待进程j释放权限
	flags[i]=1;    //进程i获取权限
	/*临界区*/
	flags[i]=0;    //进程i释放权限
	/*剩余区*/
}
```

违背了**忙则等待**

作为临界资源的变量在执行读写时可能没有在一个CPU周期内完成
原子变量：访问这个变量时，读写操作不会被打断

##### peterson算法

- `flags[i]`：进程i是否希望进入临界区
- `turn`：规定进程进入临界区的顺序

```Cpp
while(true){
	flags[i]=true;
	turn=j;    //权限让给j进程
	while(turn==j&&flags[j]);
	/*临界区*/
	flags[i]=false;
	/*剩余区*/
}
```

#### 硬件机制

忙等

##### 关中断

关中断可以实现原子变量，互斥访问

缺点：
1. 独占CPU所有权
2. 与外界失联（IO会通过中断方式通知CPU）
3. 不适用多处理器

##### 硬件指令

硬件指令在CPU中一次性执行完，不会断开

1. TSL指令：Test&Lock，返回原来的锁的值并上锁，具体实现与CPU架构有关
	```Cpp
	//全局变量lock
	while(true){
		while(TSL(&lock));
		/*临界区*/
		lock=false;
		/*剩余区*/
	}
	```
2. swap指令：交换两个变量的值
	```Cpp
	lock=false;    //全局变量lock
	while(true){
		local key=true;    //本地变量key
		while(key){
			swap(&lock,&key);
		}
		/*临界区*/
		lock=false;
	}
	```

#### 互斥量

##### 互斥锁

互斥锁底层使信号量，资源值只能为0或1

互斥锁（mutex）：锁没被释放时，将访问进程放入等待队列，只能通过其他进程的unlock接口将等待队列的进程放入就绪态

不适合等待时间极短的进程，保护现场和恢复现场浪费了大量时间

##### 自旋锁

自旋锁（spin lock）：进程不进入等待态，自己执行`while(条件)`忙等，条件满足时可以立即执行后面的语句

适合等待时间极短的进程，多用于多核CPU，一个任务在等待条件满足，另一个任务使条件满足，条件满足后等待的任务能立即解除等待；缺点是CPU消耗较高

##### 快速用户空间互斥

futex（快速用户空间互斥）：允许进程在用户空间自旋一段时间，若此期间锁未释放，该进程切换到阻塞态

### 同步

#### 信号量

信号量（semaphore）本质上是一个与临界区绑定的数据结构

只能靠PV接口改值：
- P原语：申请资源，若资源不够则阻塞等待
- V原语：释放资源

实现：
1. 整形信号量，仍然是忙等
	```Cpp
	int S=1;    //信号量资源
	P(){
		while(S<=0);    //忙等
		S--;
	}
	V(){
		S++;
	}
	```
2. 记录型信号量
	```Cpp
	struct semaphore{
		int s;    //资源数
		queue_t bq;    //阻塞进程的队列
	}
	P(semaphore S){
		S.s--;
		if(S.s<0){    //资源不够
			将当前进程的task_struct入队S.bq
			执行schedule()调度函数让其他进程占用CPU
		}
	}
	V(semephore S){
		S.s++;
		if(S.s<=0){    //V操作前资源处于不够状态，V操作后有进程获得资源
			从S.bq队列中调度某个进程放到就绪态
		}
	}
	```

##### 生产者消费者模型

通过大小为n（n个数据）的缓冲区（临界资源）进行生产和消费

- `semaphore mutex=1;`：缓冲区有互斥需求
- `semaphore empty=n;`：空位个数，即还能生产`empty`个数据，生产者使`empty`减少，消费者使`empty`增加
- `semaphore full=1;`：缓冲区已生产的数据个数，消费者使`full`减少，生产者使`full`增加

```Cpp title:"生产者"
void producter(){
	while(true){
		生产一个新数据
		P(empty);
		P(mutex);    //上锁
		将数据放入缓冲区
		V(mutex);    //解锁
		V(full);
	}
}
```

```Cpp title:"消费者"
 void consumer(){
	 while(true){
		P(full);
		P(mutex);    //上锁
		从缓冲区取出一个数据
		V(mutex);    //解锁
		V(empty);
		消费该数据
	 }
 }
```

# 调度

多道程序设计中，调度程序通过调度算法将多个任务放在同一个CPU中

进程调度：调度策略，上下文切换

所有调度都是基于**task_struct**指针

几乎所有进程的**IO事件**和**计算**都是交替进行的，进程类型可以分为：CPU密集型（计算密集型），IO密集型

**空闲进程**：当所有程序的任务都处理完后，CPU会运行空闲进程，作用是暂时占着CPU

## 三种调度层次

- 高级调度：调度对象是**外存**中等待的作业，将作业从外存调度到内存中；在分时操作系统，实时操作系统中不涉及
- 中级调度：**内存**中的调度，调度对象是暂时不能运行的进程，比如缺乏一些资源（内存）
- 低级调度：调度对象是**进程**（内核级线程），在就绪队列中选择某个进程获得CPU资源

## 进程调度的时机

1. 创建一个新进程
2. 进程的退出
3. 进程时间片用完（中断）
4. 可抢占式系统，更高优先级的任务进入就绪队列，触发任务调度
5. 阻塞发生
6. IO中断

## 进程调度方式

- 非抢占调度：进程已经在CPU上运行了，等待其自动放弃CPU（进入等待态，终止），就是队列
- 抢占调度：可以实现交互，原则：
	- 优先级
	- 短进程优先
	- 时间片轮转

## 调度算法的指标

1. 资源（CPU）的利用率 = CPU有效工作时间 / (CPU有效工作时间 + CPU空闲时间)
2. 周转时间T = 任务完成时间 - 任务到达时间
3. 吞吐量：单位时间内完成的作业数
4. 响应时间：提交请求开始到OS对该作业做出响应的时间

## 调度算法分类

三种环境：
- 批处理操作系统（Batch）：处理大规模的数据，适合使用非抢占式算法（简单高效，减少不必要的切换开销）
- 交互式系统（Interactive）：需要确保系统的**响应性**和公平性，避免一个进程长时间占用CPU，需要使用抢占式算法
- 实时操作系统（Real Time）：强调**实时性**，必须使用抢占式算法
